Pruebas obligatorias

Tras cada tarea, Colmena ejecuta los tests del proyecto (los detecta por package.json, pytest, go.mod, Cargo.toml, o usa el comando que indiques). Si fallan, la tarea vuelve al ejecutor con la salida del error sin pasar por el revisor.

Revisión por IA

Tras los tests, el rol revisor inspecciona el entregable y aprueba o devuelve la tarea. Es la parte más cara si usas un modelo grande; con DeepSeek como revisor cuesta céntimos. Desactivada, una tarea se aprueba en cuanto pasan los tests (o si no hay).

Git y GitHub

Estas opciones también están en el panel Repositorio de la pantalla principal (con clonado y selección de repo). Si el workspace (o su único proyecto) es un repositorio git, cada objetivo trabaja en una rama colmena/… y cada tarea aprobada se commitea. Push y pull request son opcionales; la PR necesita GITHUB_TOKEN (pestaña Claves API) y el push usa tus credenciales de git habituales.

Se guardan en un archivo .env local en tu PC (carpeta de datos de Colmena) y nunca salen de ahí salvo hacia el proveedor correspondiente. Deja el campo vacío para no cambiar la clave.
